# apps/web

Frontend en Astro con salida estática, islas React (una grande por rol: `/padres` y `/nino`) y Tailwind CSS 4. Habla con la api por HTTP en `/api/*`; en Vercel esa ruta se reescribe hacia la api (mismo dominio, cookies first-party, sin CORS). En desarrollo, el proxy de Vite (`astro.config.ts`) hace lo mismo hacia `http://localhost:3000` (o `API_DEV_URL`).

- Textos de UI en español, tuteando. El diseño se hace con la skill Impeccable: `PRODUCT.md` (producto), `DESIGN.md` (sistema visual) y `.impeccable/surfaces/` (brief y contrato de dirección de cada superficie). El mundo visual es una placa de construir: el fondo es una placa base con pernos, cada recuadro es una placa (`plate`) y cada botón un ladrillo que se hunde (`brick`). Un ladrillo sólido es tiempo disponible y uno punteado es tiempo usado (1 ladrillo = 10 min). Hay tema claro y oscuro: los colores son tokens de `src/styles/global.css` con un valor por tema (`[data-theme="dark"]`); `Base.astro` aplica el tema antes de pintar y `lib/theme.ts` lo cambia (Automático, Claro u Oscuro, guardado en el dispositivo). Nunca un color fijo que no cambie con el tema, salvo el blanco sobre una placa de color.
- Dev: `bun run dev` sirve la web en http://localhost:4321 y la api en http://localhost:3000. Con el proxy, `BETTER_AUTH_URL` del `.env` de la raíz tiene que ser `http://localhost:4321`.
- Variables: la web lee el `.env` de la raíz (`vite.envDir`) y, en Vercel, `process.env`. Solo usa las que declara el schema de `astro:env` (`VAPID_PUBLIC_KEY` y `GOOGLE_CLIENT_ID`, ambas públicas, se fijan en el build). Si Google no está configurado, el login no muestra el botón.
- `vercel.json`: configuración del proyecto de Vercel (build con turbo, salida `dist`) y la reescritura de `/api/*` hacia `API_ORIGIN`: la api de producción en Production y la de dev en Preview (cada preview de PR habla con la api de dev). El destino es `$API_ORIGIN` con `"env": ["API_ORIGIN"]`: Vercel lo resuelve en cada petición con el valor que la variable tenía al crear el deployment, así que el archivo es estático. `API_ORIGIN` tiene que ser de tipo Config: Vercel no expande un Secret en la reescritura. Si falta o es un Secret, el build no falla, pero `/api/*` entra en un bucle de redirecciones sin llegar a la api. No lo pases a `vercel.ts`: Vercel rechazó la reescritura calculada en el código antes de construir, y para compilarlo instala dependencias con un Bun que no lee nuestro `bun.lock`. Su `ignoreCommand` (`scripts/vercel-ignore.mjs`) salta el build cuando el cambio solo llega a la web a través de la api (de ella solo usa los tipos) y, en producción, en todo commit que no sea el release de la web. Si la web empieza a importar código (no tipos) de otro paquete del workspace, decláralo en su `package.json` y no lo marques `--type-only`. El paso a paso está en [docs/deploy.md](../../docs/deploy.md).

## Estructura

- `src/pages/`: una página por ruta. `padres/[...path].astro` y `nino/[...path].astro` generan un HTML por pantalla del enrutado interno (`getStaticPaths`), así un reload o el enlace de un push abren la pantalla correcta. `/` es la landing informativa (qué es, para qué sirve y cómo funciona), estática con dos islas en `src/landing/`: la sesión de ejemplo y el acceso («Entrar», o «Ir a mi inicio» si ya hay sesión). Ya no redirige: la PWA abre en `/padres`. `/login` es la entrada de los padres y `/nino/entrar` la del niño (una ruta estática, que gana a `nino/[...path]`).
- `src/parents/`: la isla de padres (`ParentsApp.tsx`: guard, shell y rutas con wouter bajo `/padres`) y sus pantallas: Inicio (`Home.tsx` y `home/`), Nueva sesión, Historial, Reglas, Bonos y Cuentas.
- `src/child/`: la isla del niño (`ChildApp.tsx`: guard, shell y rutas bajo `/nino`) y sus pantallas: Inicio (`Home.tsx`, `home/`: baterías de ladrillos y «Ahora» de solo lectura), Pedir (`Ask.tsx`, `ask/BrickPicker.tsx`), Tareas y Avisos. `requests.tsx` reúne el pedido pendiente y las respuestas; `errors.ts` dice los errores con la voz del niño y cae a `lib/errors.ts`. El niño nunca ve iniciar, pausar ni detener.
- `src/entry/`: las islas públicas: login de padres, login del niño (`ChildLoginPage.tsx` y el teclado `PinPad.tsx`; el navegador recuerda el usuario, nunca el PIN) y recuperación. Su marco común (`PublicFrame.tsx`) muestra abajo a la derecha la versión de la web, que lee de este `package.json` (la escribe el release, no se edita a mano).
- `src/components/`: piezas compartidas por las dos islas: controles (`ui.tsx`: placas, botones-ladrillo, campos hundidos), toasts, la marca (`brand.tsx`), los ladrillos (`bricks.tsx`, con el muro de la semana, la torre de la sesión y el hueco «por ganar»), el selector de tema (`ThemeSetting.tsx`), los sonidos de la alarma (`SoundSettings.tsx`, en Cuentas y en Avisos), la placa de Inicio que dice si la pestaña puede sonar (`TabAlarm.tsx`), el título de paso numerado, el marco de pantalla completa y los providers.
- `src/lib/`: cliente tipado `hc<AppType>` y `call()` (`api.ts`, con los errores de la api como `ApiError`), Better Auth (`auth.ts`), TanStack Query (`queries.ts`, consulta cada 5 s en las vistas en vivo), comandos con toast (`useCommand.ts`), guard de rol (`guard.ts`, cada rol con su login), reloj del servidor (`clock.ts`), cuenta regresiva (`timer.ts`), alarma de la pestaña (`alarm.ts`), sus sonidos (`sounds.ts`: el catálogo, generado con Web Audio, y lo que eligió este dispositivo) y su voz (`voice.ts`: lee el aviso con las voces en español del navegador), Web Push (`push.ts`, que dentro de la app Android registra el token de FCM en vez de la suscripción), la app Android (`native.ts`), textos de error (`errors.ts`) y formatos en la zona de la familia (`format.ts`).
- App Android (`apps/mobile`): la misma web dentro de Capacitor. `lib/native.ts` es lo único que habla con el plugin propio (`TimeCraft`) y los de Capgo, y siempre mira `isNativeApp()` antes; los plugins se importan dinámicamente para no pesar en el navegador. En la app: el interruptor de avisos registra el token de FCM (`/api/native-push-tokens`), la pestaña no suena con Web Audio sino que hace sonar el teléfono (`ringNative`, al segundo exacto; el teléfono ignora el push que llega después) y un toque en la página lo detiene, la voz es la de Android (el WebView no tiene voces), Google entra con el selector de cuentas del teléfono (ID token), el lado de los padres se abre con la huella (`components/AppLock.tsx`), el niño puede entrar con la huella tras un primer ingreso con PIN, Cuentas y Avisos muestran la lista de `components/NativeAlarmSetup.tsx`, y la landing salta al lado que usó el teléfono la última vez. Cambiar los sonidos de `lib/sounds.ts` pide regenerar los WAV de la app (`bun --cwd=apps/mobile run sounds`).
- `public/sw.js`: service worker de Web Push (muestra el aviso, abre la página al tocarlo y se lo pasa a las pestañas abiertas; una sola, la de adelante si hay, suena). `public/manifest.webmanifest` e `icons/`.
- `brand/`: el logo. `mark.svg` (el ladrillo amarillo con el reloj) es la fuente; `bun run brand` (`scripts/brand.mjs`) genera a partir de él el logo con el nombre en trazos (`logo.svg` para fondo claro y `logo-dark.svg` para fondo oscuro), `public/favicon.svg`, `public/favicon.ico` y los iconos de `public/icons/` (app, adaptable, Apple y la silueta del aviso push). Los archivos generados se commitean; si cambias la marca, cambia también `BrandMark` en `src/components/brand.tsx`.

## Tiempo real

- El servidor manda: la web nunca calcula saldos. Solo cuenta el restante en vivo a partir del inicio, la duración y las pausas que devuelve la api, con la hora del servidor (`serverTime` en cada respuesta del cronómetro corrige el desfase del reloj del teléfono).
- Polling de 5 s con TanStack Query, solo con la pestaña visible. Un push con la pestaña abierta refresca todo al instante.
- Detener el fin en un dispositivo lo calla en todos: el toque llama a `POST /api/sessions/:id/stop-alarm` y la api manda `alarm_stopped` a la familia (también al detener la sesión pasado su fin). Ese push calla la pestaña (`stopRingingFromPush`) y el service worker cambia el aviso por uno sin sonido. Las alarmas se identifican por la etiqueta del push (`session-…`, `request-…`, `report-…`).
- La alarma de la pestaña suena (Web Audio) y vibra al aviso previo y al fin, en las dos islas; del lado del niño, también cuando una sesión programada le deja empezar. Complementa al push, no lo reemplaza: Android congela los timers de las pestañas en segundo plano.
- Un push que llega con la pestaña abierta también la hace sonar (`PushAlarm` en `providers.tsx`), con el sonido que eligió el dispositivo. Si el dispositivo tiene la voz activada, después del sonido lee el aviso con las mismas palabras del banner o del push (`ringOnce` recibe esas palabras); el fin que se repite solo dice el título. `ringOnce` evita que la misma alarma suene dos veces (el temporizador y el push, por sesión, pedido o reporte). Una pestaña oculta deja de consultar y no ve una pausa: si el navegador tiene push, su temporizador se calla y suena el push, que el servidor solo manda si la alarma sigue en pie.
- En la computadora una pestaña de fondo no se congela, así que la alarma suena detrás del juego. Mientras haya una alarma por delante, Inicio dice si la pestaña puede sonar (el navegador la deja muda hasta el primer toque) y, en la computadora, cerrarla pide confirmación (`useLeaveGuard`; `signOut` la desactiva).

No debe:

- Contener reglas de negocio ni calcular saldos: los recibe de la api. Solo calcula el restante en vivo del cronómetro a partir de lo que devuelve el servidor.
- Importar `packages/db` ni manejar secretos: todo lo que llega al navegador es público. De la api solo importa tipos (`AppType`).
- Usar SSR ni un adaptador de Astro: la salida es estática.
- Usar APIs exclusivas de Bun.
- Copiar el contrato de dirección de `.impeccable/` al código o a cualquier archivo que llegue al navegador.
